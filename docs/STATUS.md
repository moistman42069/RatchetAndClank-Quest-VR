# Status

What this port does and does not do yet. "Proven" names the strongest test each item has had.

**Builds.** 0.1.0 (version code 1) was tried on a Quest 3 on 30 October: it ran at 72 Hz, no save could be made, the
tools sat at wrong angles and Ratchet could not walk (the left controller's pose was never valid). 0.1.1 fixed the
first two on PC and logs each controller's binding, the walking still to be seen on a headset. 0.1.2 (version code 3, 1 November) is the first build with Rerac-vr's features below and the first public release,
a test build to gather headset logs; 0.1.3 (version code 4) lets the hand be empty, as Rerac-vr's; 0.1.4 (version code 5) fixes the game not starting after an update (tools/test_update_folders.sh); 0.1.5 (version code 6) draws and keeps active what the eyes see, not only what the game's camera does, and draws all the scenery by default; 0.1.6 (version code 7) fixes the VR mod not loading on the NTSC-U disc (a black headset since 0.1.2; tools/check_hooks.py now stops any build that would repeat it); 0.1.7 (version code 8) adds Max draw distance, on by default: every moby and particle drawn as far as the eyes see, the far ones in view kept running, and those the game hid for a scene run once in view so they show again; 0.1.8 (version code 9) points the guns where the controller points (OpenXR's aim pose) instead of along its handle, which shot high on Quest controllers (a tester had to point at the floor to shoot ahead), and adds the pause menu's VR Hands page: Gun angle, Gun size and Hand size; 0.1.9 (version code 10) leaves out the thin line drawn between Ratchet's hands (the rest of him closed onto his elbows, its skin stretched from one to the other), seen by a tester in cutscenes through his eyes; 0.1.10 (version code 11) works through a tester's list from 0.1.7 to 0.1.9 (the ship's landing seen from his eyes along his heading, a gun drawn tiny after the ship, the glove's bomb and the Pyrocitor's flame wandering, the hands off the items at another Hand size, the off-hand's spot on two-handed guns, two hands on the left hand's gun, its ammo, the vendor's bolts at the edge of the view, a crash back from third person) and adds five rows to VR Hands; 0.1.11 (version code 12) draws a bolt's twinkle (the game's glints) in the world, on the bolt, not on the HUD's layer where it hung before the eyes (an owner's report on 0.1.10), with the launcher's Sparkles on the bolts, on by default; 0.1.12 (version code 13) works through two testers' lists and the owner's (a row below); 0.1.13 (version code 14) works through the owner's list after playing 0.1.12 on a Quest 3, a tester's notes on 0.1.12 (the US disc) and a player's ask for buttons in place of the arm moves (the rows after it). 0.1.14 (version code 15) works through the owner's notes and video of 0.1.13 on a Quest 3, and adds the PC VR release: the same launcher as RatchetClankVR.exe, run on SteamVR's null driver only (the rows after it). Everything below "PC run" is the PAL disc on a PC with a simulated
headset; when 0.1.2 was released none of it had been on a Quest. Walking is now confirmed on a Quest on 0.1.2 (the owner, on the first level), and 0.1.12 has run on the owner's Quest 3 with the PAL disc (their logs of 4 November, which showed the ledge climb below); the rest of the headset checklist is open. The NTSC-U disc has been started once, by a tester on 0.1.5: the game ran but refused the VR mod (fixed in 0.1.6, checked by its hook table, not by a run: no NTSC disc is set up here).

## Why OpenRAC is the engine

| | ReRAC + Rerac-vr | OpenRAC |
|---|---|---|
| Measured by its authors | Ryzen 5 5600 and RTX 3090: 51-59 fps near spawn, 14-25 fps in sustained Blaster fire | Runs on phones with OpenGL ES 3.2 |
| The game's code | Rewritten in Rust on Bevy, about 5,000 entities an eye | The original code, recompiled |
| VR | Complete gameplay, PC only | The view and OpenXR hooks, no VR game |
| Discs | SCUS-97199 only | SCES-50916 v2.00 and SCUS-97199 v1.00 |

A Quest 3's CPU is roughly two to three times slower than that desktop chip, so Rerac-vr's own numbers
rule Bevy out on the headset. Rerac-vr's design is ported into `vr/` feature by feature instead.
`rac1-mods` holds no VR code; the VR groundwork is OpenRAC's mod interface (`on_views`, `setup_vulkan`).

## The engine's version

OpenRAC `develop` at `91b67c67` (2026-11-09, mod interface 1.14), from 0.1.18; 0.1.17 was on 0.10.1 (`293cb5cc`,
2026-10-30). Since 0.10.1: the decompilations as submodules (`python tools/sources.py init` checks them out and
patches them), the mod interface's 1.12 to 1.14 (a hero driven by a mod, collision, props, sounds, the camera; what
RAC-Board and the multiplayer mod build against), the menus' catalogue, the sound mixer, Draw distance's Unlimited,
co-op and crossplay. The port's own table of calls (`openrac_api`) is upstream's 152 in its order, then this fork's
13 after them, so a mod built against upstream loads here. 0.10.0's Android mods, Exit item and texture fixes, and
0.10.1's Android full screen, lower input lag (late camera latch, low-latency frames) and rac1 fixes (Batalia's ice,
the red planes after a flight, fires at the sides of a wide view) are in it.
`patches/0001-quest-vr-frame-path.patch` is the Quest's change to it: the eyes drawn without a third
picture for the window, movies in the headset, the window's swap left to OpenXR, an absolute eye pose,
MSAA for the eyes, `on_before_capture` for the weapon in the hand, the calls the VR mod uses beyond the
SDK's (a body drawn as its two arms, joints and a model's points through a joint, a second hand item, rectangles of
the 2D or of the window's picture standing in the world, sprites turned to the eyes, the helpdesk off on a new game (unused by the mod from 0.1.17),
the hooks the mod adds to the game's tables), and the game's view tests opened
while a headset draws (`picture_wider` 18, some 85 degrees a side): the mobys beside the player stay
"drawn" for the game, so active and making their effects, and the seas send their side blocks.
Sideways only, as upstream's widening is, and nothing behind the game's camera: so each eye also counts
for itself (view flag 8, `openrac_game_eye_view`): a moby it sees is drawn and "drawn" for the game, the sphere
test that stands for what the player sees passes it, and the particles and sky sprites it sees are drawn. Checked against 0.10.1: the new
"keep the last picture" frames go through the same patched path; the camera latch reads only a real
gamepad, which the headset does not have; low-latency frames do nothing on OpenGL ES with no window
swap. `tools/build_quest.py` stops unless OpenRAC is at the pin with the patch applied and both rac1
decompilations checked out.

## OpenRAC's later work (0.1.12)

Upstream `develop` is 118 commits past the pin. Moving the pin would bring 17,267 files and 2.3 million lines, Going
Commando's included, and there is no launcher release newer than launcher-v0.10.0, so its fixes were taken one by one
into the patch.

**Taken:** the PAL disc's freeze after picking Quartu, and drowning on Quartu; the landing and the vendor's scene with a
full moby list (51d283b5); the vendor screen's sampler (the grey Pyrocitor); screen fills reaching the edges; baked
visibility on OpenGL (checked against a VR head, below); Clank's shadow; the flight between planets; the collision's -0
and vf2w (not the real VU0 part); mod interface 1.11; the Difficulty mod's Blarg fix and the Item randomizer's fix, by a
newer rac1-mods pin; Xbox button icons and Button swap, bundled; Add a mod file.

**Not taken, each with its reason:**
- 857ff04a, the diagonal stick: pad.h's stick_byte already pushes past the dead zone.
- 8b862810, the distant fade: 1,388 lines with 20 conflicts, for the Original draw distances and the Performance preset
  only, neither of them the default.
- 101866a8 and 993fc641, the HUD at the edges: the Quest puts the HUD at the centre.
- f0593f17 and gl_SampleMask: the pin has none of what they change.
- Vulkan only (dfd4d68a, 8d7db4c4, d3b198cc, cf82b84e, the render graph, 72149480): the Quest draws with OpenGL ES.
- Windows x64 only hostgen (ea53e836, 53a94d07).
- 86b9d821, asmc: it does not apply, and it is for Going Commando.
- ce30ee74: it needs the Lombyte sync, and the pinned NTSC draw_vendor_effects has none of the code it changes.
- 88dddea6 and eefdcd12, the Android hint: upstream reverted it, and VR sets its own with xrPerfSettings.
- 29756bba: it fixes upstream issue #148, whose cause is not in the pin.
- b27f268f, the expanded limits, and the decomp syncs.
- c6f86bc3, 29 hook points: their names clash with this project's own hooks.
- ae2fed40, mod interface 1.12: unreleased, 3,877 lines.
- fb380336, the Audio tab: 3,921 lines.
- 6b4b4837 and b4921fa7, the shader caches: large.
- The FOV slider, HDR, the FFT ocean, fur, motion blur, the free camera, the shared in-game menu (with 45c39b79 and
  bb92f000), Safe rendering and the crash breadcrumbs: for a flat screen, heavy, or for debugging.
- Upstream's open issue #262 is a desktop launcher crash, not one the Quest has.

**rac1-mods not bundled:** lock-strafe (it fights VR's facing hooks), live-splits (it needs a LiveSplit server),
dualsense and keyboard-mouse (hardware the Quest does not use), multiplayer and archipelago (they need a server and are
untested; either can be added as a file). Xbox button icons and Button swap are bundled off; Ammo at the most is on.
